# Near-the-loop: always-on agents (research, 2026-10-27)

## Definitions
- **In the loop (HITL):** agent waits at a gate for human approval. **On the loop (HOTL):** agent acts; human monitors and can override. **Out:** no oversight. Vendor glossary definitions, not a standard: https://decagon.ai/glossary/human-in-the-loop-vs-human-on-the-loop , https://blogs.fluencysecurity.com/human-in-vs-on-the-loop/
- **Near the loop:** I found **no established source** for this term. The closest is "selective, not continuous" involvement, where something specific triggers it (risk, uncertainty, ambiguity, policy) and the trigger is a separate system component: Cheng & Cheng, arXiv 2604.23049 (Apr 2026) https://arxiv.org/abs/2604.23049 . Working meaning: the agent acts; the human is pulled in only for exceptions.
- **Ambient agents** (Harrison Chase, LangChain, Jan 2025): react to event-stream signals, not prompts. Three HITL patterns: **Notify**: flag the event, take no action. **Question**: ask the human to unblock the agent. **Review**: propose an action and wait for approval. Ambient is not fully autonomous. https://blog.langchain.com/introducing-ambient-agents
- **Levels of autonomy** (Feng, McDonald, Zhang, UW/Knight Institute, 2025), named by the user's role: L1 Operator, L2 Collaborator, L3 Consultant, L4 **Approver** (user involved only in risky or pre-specified cases), L5 **Observer**. Autonomy is a design choice, separate from capability. https://arxiv.org/abs/2506.12469
- **CSA Agentic AI Autonomy Levels & Control Framework v2** (Mar 2026): L0–L5 on the SAE J3016 model, rated on authority, scope, reversibility, impact and duration, with controls per level. *The PDF says it was AI-assisted and has not been officially reviewed by CSA.* https://labs.cloudsecurityalliance.org/research/agentic-ai-autonomy-levels-control-framework-v2-csa-styled/
- **Anthropic, "Measuring AI agent autonomy in practice"** (Feb 2026): experienced users auto-approve more (~20% to 40%+ of sessions) and interrupt more (~5% to 9% of turns). On complex tasks, the agent stops itself more often than humans interrupt it. About 0.8% of actions look irreversible. The post concludes that oversight means "being in a position to intervene when it matters," not approving every action. https://www.anthropic.com/research/measuring-agent-autonomy
- **Heartbeat** (OpenClaw): periodic agent turn (default 30 min) over a short HEARTBEAT.md checklist; silent token when nothing is due. *Unverified/changed:* the official docs now say heartbeat is **retired** and replaced by automation jobs with `activeHours`, `idleOnly`, `skipIfScratchEmpty`, `NO_REPLY` and `no_change` (which suppresses delivery). https://docs.openclaw.ai/gateway/heartbeat .

## Design rules for a warden agent (arbitrary signals, human near the loop)
1. **Map every signal to an outcome: ignore, act, notify, ask, or review.** Default to acting silently. Only "review" blocks. (LangChain ambient agents)
2. **Gate on reversibility/blast radius, not signal type.** Reversible+low-impact: act. Irreversible/wide: review. (CSA reversibility/impact dimensions; Anthropic: only about 0.8% of actions are irreversible, so gating those costs little.)
3. **Pick an autonomy level per action class and make it explicit:** L4 Approver for production writes, L5 Observer for read-only diagnosis. Raise a level only after a clean audit log. (Feng et al.; Azure SRE Agent's Review vs Autonomous modes, Review recommended for production: https://learn.microsoft.com/azure/sre-agent/run-modes)
4. **Separate "ask first?" from "allowed at all?"** Both must pass. Diagnosis read-only; remediation opt-in. (Azure SRE run modes; HolmesGPT read-only default, *third-party*)
5. **Make silence the default output.** A heartbeat or periodic check that finds nothing returns `NO_REPLY`/`HEARTBEAT_OK` and sends nothing. Use active hours and idle-only scheduling, and skip the check when its scratch is empty. (OpenClaw docs)
6. **Use a cheap trigger before the expensive model.** Score events structurally or with a calibrated classifier, and call the LLM only when the score is high enough. (Liu et al., arXiv 2605.30152; PRISM, ICLR 2026, *slides only*: https://iclr.cc/media/iclr-2026/Slides/10007161.pdf)
7. **Back off on ignored interrupts.** If the human ignores a notification class, raise that class's threshold. (Proactive programming-support study, arXiv 2502.18658: https://arxiv.org/abs/2502.18658)
8. **The agent should stop itself when uncertain**, for example to choose between approaches, to get access, or when the request is ambiguous. Don't wait for the human to catch it. (Anthropic measuring-autonomy reasons breakdown)
9. **Human interaction is its own layer:** one inbox, explicit intervention conditions. (LangChain Agent Inbox; Cheng & Cheng 2604.23049)
10. **Durable state across wakes:** progress file, task list, run history = resume + audit trail. (Anthropic long-running harness posts, *primary page not opened*; OpenClaw job run history)
