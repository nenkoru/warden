# Why the 27B did badly in Warden, and what changed

The week-44 log ([experiment-27b.md](experiment-27b.md)) shows 7 tasks and 3 merges, all of them trivial. The failures were loops into the 25-step limit, malformed tool calls and wrong edits. Issue #18 alone took 9 attempts and about 12.7M prompt tokens, and #10/#11 stayed open. The owner runs the same model, qwen3.8-27b on the same vLLM behind the same LiteLLM, in oh-my-pi (omp) and gets good results. So the gap is in the harness, not the model. This note compares Warden's coder loop with omp's (source: can1357/oh-my-pi at ef3293b and badlogic/pi-mono at d5c4b80) and maps each failure to a concrete difference.

## What the numbers already say

- **Prompts were huge.** #18 averaged about 56–64k prompt tokens per step: 4.4M over 69 steps, then 8.3M over 148. `read_file` returned whole files (up to 200 KB, with no window), and there was no search tool. To find "the digest act" the model had to read 600–1000-line files whole, and every one of them stayed in the conversation for the rest of the run.
- **Almost no reasoning.** Output was 9.4k tokens over 69 steps, about 136 tokens per step: a bare tool call, no thinking. omp runs this model as `litellm/qwen3.8-27b:high`, with thinking on. Warden sent no thinking or reasoning field at all. This has not been confirmed against the live model yet: the replay below compares the two.
- **#18 could not be finished with files.** Its "done when" is "#10 and #11 are closed", but the coder had file tools only. The issue also pointed at the wrong places (`internal/github/`, a "digest skill"). The digest lives in `internal/builtin/github_note.go`, and it already kept a single digest issue (9343be6, the day before). The right answer was a test, or nothing, plus a note that closing the duplicates is Warden's job. Instead the model searched with whole-file reads until the step limit hit, and the PR that finally merged (#24) changed the roadmap's dedup instead.

## Failure class → harness difference

| failure (log) | Warden (before) | omp | changed |
|---|---|---|---|
| **loop** (6×, "stopped after 25 steps") | A hard 25-turn limit with no warning. The worktree is dropped and the issue deferred, so the next tick starts again from zero with no cap (#18: 9 runs). No search tool, so exploring burns turns. | No turn limit. A repeated-call guard tells the model "NEVER call X with those arguments again", and recovery prompts handle empty or announced-but-not-made calls. | `grep` and `find` tools. Turns default to 50. Warnings at 3 turns left and on the last turn. The same call returning the same result gets a one-line answer instead of the result, and the third time ends the run as a loop. A run that got stuck is retried once on a later tick; the second time that day it goes to the owner. |
| **tool-call** (15/338 calls) | Tool names and arguments the model was not trained on (`read_file`, `replace_in_file` with `old`/`new`). An unknown tool got `error: unknown tool X` with no list. Bad JSON got a bare parse error. A call that vLLM's parser left in the text ended the run as a final answer ("made no change"). | Tolerant argument handling: JSON repair, double-encoded values, a lone string under the wrong key. "Did you mean". The raw arguments are returned with the error. Malformed-call retry prompts. A qwen3 text-call parser. | Pi- and Claude-Code-style names (`read`, `grep`, `find`, `edit`, `write`), with the old and common names as aliases (`read_file`, `str_replace`, `list_files`, …). Argument aliases (`file_path`, `old_string`/`old`/`oldText`, …). JSON repair for fences, double encoding and trailing text. The error tells the model how to escape, and echoes its arguments. Unknown tools list the real ones. Hermes `<tool_call>{…}` and Qwen XML `<function=…>` calls in the text are run as calls. An unparseable one gets up to 3 retry prompts. |
| **wrong-edit** (2×, plus "made no change") | `replace_in_file` accepted only exact text. A miss said only "old text must occur exactly once (found 0)". Go files use tab indentation, which the model often writes as spaces. After a miss the model re-read the whole file or rewrote it with `write_file`: a whole Go file JSON-escaped in one call, which caused bad arguments and lost lines. | For Qwen 3.8, omp uses its replace mode, not hashline (`utils/edit-mode.ts`). It tries an exact match, then a normalized one, then a fuzzy one at ≥95% that must be unique, and fixes the indentation. A miss shows the closest match with its line number and similarity. | `edit{path, old_string, new_string, replace_all}`. It tries the exact text, then a match ignoring whitespace and typographic quotes, then a unique ≥95% line-window match. Indentation is mapped to the file's. On a miss the error gives the closest lines with numbers and their exact text, to copy from. If several places match, it gives their line numbers. Line-number prefixes copied into `old_string` are stripped. |
| **context** (no context-limit hits, but 56–64k-token prompts) | Whole-file reads, kept forever. Append-only. | `read` shows 300 lines by default with a continuation note. Old tool results are pruned before compaction. Superseded reads are dropped. | `read{path, offset, limit}`: 300 lines by default, at most 2000 lines / 50 KB, lines over 500 characters cut, and "[lines A-B of N. Use offset=… to continue.]". grep returns at most 100 matches. Once a prompt passes `context_budget` (64k), every tool result but the last 6 becomes a one-line note, all in one sweep so the prefix cache breaks rarely. The task now includes the repository's directory layout, so the first calls are not spent listing files. |
| **prompt** | A list of rules, no way of working. The maintainer skill said "find where the concept already lives" with nothing to find it with. Nothing said what to do with non-file steps. | A short role, a tool policy ("use read ranges, not whole files", "never open guessed files", "re-read after a tool failure"), and a workflow. | A short workflow: plan in 2–4 lines, locate with grep or find, read ranges, edit, add a test, never repeat a call, stop with a summary. GitHub steps (closing or labeling issues) are Warden's: the coder skips them and says so in the summary. Paths in the issue may be wrong, so check them. The safety rules are unchanged. |
| **reasoning** | No thinking or reasoning parameter was sent. The transport also stripped `reasoning_content` from every response (`stripReasoning`), so on the next turn the model had lost its own reasoning between tool calls. The Qwen template keeps that reasoning for turns after the last user message, so the vLLM prefix cache never matched either, and every step re-filled the whole prompt. | `:high`. For local backends, omp sends `reasoning_content` back with the earlier turns (`replayReasoningContent`, `preserve_thinking`) precisely so the template and the cache stay intact. | `reasoning = "replay" \| "drop"` on a brain. The default is replay for a free (local) brain and drop for a paid one, as before. `extra_body` (for example `chat_template_kwargs = { enable_thinking = true }`) adds request fields as they are. It is off by default until the replay shows it helps. |

The long idle stretch on 2026-10-29 (10:05 to the night window) was not a harness problem. #18's PR had used its one fix round, and the roadmap opens at most 3 issues a week, so there was nothing to work on. That is backlog starvation, not model availability.

## What changed in the code

- `internal/brain/session.go` (new): the per-run state of the tool loop. Repeat guard, turn warnings, elision, argument repair, text-call parsing. `brain.ErrStuck` separates "the model got nowhere" from "the upstream failed".
- `internal/brain/endpoint.go`: both loops (Anthropic and OpenAI) use it. New options: `MaxSteps` (default 50), `ContextBudget`/`KeepResults`, `ExtraBody`. `internal/core` exposes these as `max_steps`, `context_budget` and `extra_body` on a `[brains.*]` block, next to the new `reasoning`.
- `internal/brain/brain.go`: `Tool.Aliases`, `brain.Find`.
- `internal/core/brains.go`: `reasoning` (replay or drop) on a brain; a free brain's reasoning now goes back with its turns.
- `internal/builtin/tools.go`, `edit.go`: the new tool set.
- `internal/builtin/github_acts.go`: the coder prompt, the layout in the task, and the stuck-retry cap (`maxStuck = 2` a day per issue).
- Tests: `internal/brain/session_test.go`, `internal/builtin/tools_test.go`.

Not changed: `internal/core/orders.go` has its own older `worktreeTools` (for orders), which should move to `fileTools`. Also not changed: the maintainer skill in `packs/github-repo/` (human-only kernel), which still says "Run nothing yourself" and should name grep and find.

## The replay

`scripts/replay-27b.sh BASE_URL MODEL` runs tasks from the log against a live model, on the old tree (`origin/main`, with `scripts/replay/old_shim.go.txt`) and on this one. Each run uses a scratch worktree of the commit the task was worked on: #18 at `9ca6f67`, #16 at `223e533`. It scores tokens, steps, bad calls, how the run finished, whether the change touched the right file, and whether the changed packages build, vet and test. `WARDEN_REPLAY_EXTRA='{"chat_template_kwargs":{"enable_thinking":true}}'` adds a third run with thinking on. Nothing is pushed.
